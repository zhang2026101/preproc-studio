# 预处理工作台 · Preproc Studio

**v1.1.0**　Python 3.12 · FastAPI · OpenCV　无前端框架

AI 读图诊断成像问题 → 生成并拼接算子链 → 用指标与闸门核验 → 导出可直接配进
海康 VisionMaster 的流程配置。人工可随时增删算子、调参数，每一步都能看到中间态。

不是在线检测系统，也不是图像增强算法库。它解决的是一个具体问题：
**低对比度、光照不均的图，直接配流程参数靠猜，配完也不知道对没对。**

---

## 为什么是这个形态

### 1. 收益落在流程搭建，不在训练数据

> v1.0 原先定位为"标注辅助视图"（增强图给标注员看，标签仍落原图）。
> v1.1 起主出口改为**流程配置**：预处理成为产线流程的一部分，训练与推理走同一条链，
> 因此不再有"训练用增强图会域偏移"的问题。

现在它交付的是"这条链该怎么配"：每个节点的 VM 模块、参数、算法语义、多分辨率耗时。
`compare/` 里的原图\|增强图对照，用于配完之后核对 VM 跑出来的是不是同一条链。

### 2. 只用几何不变算子

`app/ops.py` 里 16 个算子全部是逐像素或逐邻域运算，不改变图像尺寸与空间对应关系。
因此增强视图上画的框**可以直接落到原图上**，不需要逆变换。

这条是整个方案"零成本落地"的前提。任何新增算子如果涉及 resize / crop / warp，
必须在 `ops.py` 顶部声明并配套逆变换，否则双视图标注的前提失效。

### 3. AI 可以提议，但不能定稿

见 `app/vlm.py` 与 `app/compose.py`。模型做两件事：判断“这张图是偏暗还是反光”，
以及配方库不匹配时拼一条新链。拼链时它确实会给出算子顺序和参数初值，但没有一项能直接定稿：

- 只能用 `app/ops.py` 里 16 个几何不变算子，白名单之外的一律丢弃
- 参数逐个对照 schema 校验，超出允许区间就钳制到边界
- 链首强制补灰度、相邻重复算子去掉
- 拼出来的链照样要过伪影闸门和指标排序，不合格不会被推荐

最终参数来自配方库或数值精修（`app/tuning.py` 的坐标下降，不是模型输出），
选哪条由人点。模型对参数没有像素级校准能力，它给的数字是起点，不是结论。

### 4. 代理指标不等于精度

`app/metrics.py` 的加权分只用于**排序和早期淘汰**，它衡量的是"信息量变多了"，
不是"缺陷能检出了"。

真结论只能来自两处：**VM 里跑真实样本的检出率**、**这条链在产线上的节拍**。
`use_export.py verify` 能证明"VM 配出来的和我们是同一条链"，
但它证明不了"这条链能不能检出缺陷"——这两件事经常被混为一谈。

## 快速开始

```bash
# 依赖：fastapi / uvicorn / python-multipart / numpy / opencv-python
pip install -r requirements.txt

python run.py                 # http://127.0.0.1:8770
python run.py --port 9000
python run.py --host 0.0.0.0  # 局域网给同事看
```

首次运行没有批次，界面上：
**新建批次 → 导入文件夹（或拖图上传）→ 点样本 → AI 重出方案 → 核验 → 导出**

导入走系统原生选择器：单张用「选图片」，整批用「选文件夹」（`webkitdirectory`），
两种都是浏览器读文件后上传，不用手打磁盘绝对路径。`/import_dir` 接口保留给脚本用。

想直接看到完整状态，跑一次演示数据准备（脚本默认读 `samples/`，
放几张自己的产线图进去即可；仓库不附带任何客户图片）：

```bash
python scripts/prepare_demo.py
```

界面验收脚本（`scripts/ui_test.py`、`scripts/shot_*.py`）额外需要 Playwright，
不影响主程序：

```bash
pip install playwright && playwright install chromium
```

## 接视觉模型

配置存在 `data/config.json`，首次运行自动生成，已列进 `.gitignore`。
仓库里附了一份脱敏的 `config.example.json`，可以直接复制过去再填 `api_key`；
也可以完全不碰文件，启动后在界面「设置」里填，效果一样。
用环境变量 `PREPROC_API_KEY` 也能覆盖，适合容器或 CI。

诊断来源三选一：**本地规则**（不联网，纯统计量）、**线上模型**（OpenAI 兼容接口）、
**本地模型**（内网 vLLM / Ollama，同协议）。

`app/vlm.py` 只依赖 OpenAI Chat Completions 协议，所以任何兼容该协议的视觉模型都能接。
界面上点「设置」，选服务商预设即可，**不用改代码**。

内置预设：

| 预设 | base_url | model | 图片格式 |
|---|---|---|---|
| DeepSeek（国内直连） | `https://api.deepseek.com` | `deepseek-flash` | data URL |
| 通义千问（阿里百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` | data URL |
| 智谱 GLM-4V | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-flash` | **裸 base64** |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | data URL |
| 本地 vLLM / Ollama | `http://127.0.0.1:8000/v1` | `Qwen2.5-VL-7B-Instruct` | data URL |

### 三个容易踩的坑（都已在代码里处理）

1. **图片传参格式不统一**。OpenAI / DeepSeek / 百炼认 `data:image/jpeg;base64,...`；
   智谱 GLM 只认裸 base64，带前缀直接 400。用 `image_style` 切换。
2. **`detail` 字段不是每家都认**。DeepSeek / OpenAI 支持 `detail: "low"`（缩到 512×512），
   诊断成像条件足够且省 token；不支持该字段的厂商要把它置空，否则可能报参数错误。
3. **`response_format: json_object` 不是每家都支持**。代码先带它请求，遇 400 自动去掉重试一次。

### 成本参考

诊断只传一张缩略图，`detail=low` 时单图约 200–300 token。
12 张样本各跑 3 轮候选 = 36 次调用，DeepSeek 峰谷定价下总量约 1 万 token，
按 cache-miss 输入价算不到一分钱。**真正贵的是迭代轮数，不是图片。**

## 界面

三栏：样本 / 算子链 / 预览与指标。这是编辑器的功能需要，不是营销页的卡片栅格。
视觉上刻意做成"一整张白纸被几条细线划开"，没有卡片堆叠。

### 视觉规范

色纸底 + 白色内容面 + 内嵌块，三层明度拉开。

| 层 | 色值 | 用在哪 |
|---|---|---|
| 页面底 | `#EEF0F3` 雾蓝灰 | 画布 |
| 内容面 | `#FFFFFF` | 每个面板 |
| 内嵌块 | `#E4E8EE` | 观察文字、得分区、操作条、表头 |
| 顶部色带 | `#DFE6F1` | 顶栏，同族最深一档 |

底色选雾蓝灰而不是米黄：米黄试过一版，在屏幕上偏"旧文件"，工业场景需要的是仪器的冷静感。
蓝灰与原有的淡蓝色带同族，不会出现冷暖打架。

边框、文字、滚动条全部转冷调（`#DCE1E8` / `#5E6672` / `#CDD4DE`），
否则中性灰压在蓝底上会发脏。卡片加一层 `inset 0 1px 0 #FFF` 的纸面微凸。

| 项 | 取值 |
|---|---|
| 圆角 | 卡片 8px，小元素 4px |
| 按钮 | 淡蓝灰底 `#F3F6FB` + `#DBE3EF` 边框，悬停转纯白；主/放行按钮仍为实色 |
| 按钮 | 边框常显（`#D3DAE4`），悬停底变纯白 + 边框加深；主/成功按钮悬停变亮而非变暗 |
| 阴影 | 无外阴影，只用 inset 画线或微凸 |
| 字号 | 32（得分锚点）/ 20（弹窗标题）/ 15（标题）/ 13（正文） |
| 字重 | 400 / 500 |
| 字体 | 系统栈；产品名（中文宋体 / 英文 Georgia）是全站唯一的衬线 |

画布内边距 12/16px、卡片间隙 12px，让底色在每个缝隙里露出来。

### 布局：撑满而不是收紧

三栏是 `220 / 1fr / 440`。中栏和右栏都吃满剩余高度，不留大块空色纸：

- **算子链**每行固定 120px、缩略图固定 133×100（CSS 变量 `--op-h` / `--thumb-h` / `--thumb-w`），
  链尾是固定 48px 的虚线「＋ 添加算子」占位行。
  链再长也不改行高，超出容器就在链内滚动——之前按步数均分剩余高度，
  6 步会压到 86px、2 步又撑到 260px，同一套界面在不同图上比例完全不同。
- **缩略图尺寸不再由 JS 反推**：行高固定后图也跟着定死，`fitChainThumbs` 保留为空实现，
  免得同一张卡在 2 步和 6 步时忽大忽小（历史上这里踩过"按行高反推 → 循环依赖"的坑）。
- **对比视图上下叠放**，整块统一浅色底，两张图之间是一条 1px、两端渐隐的细线。
  名称（原图 / 第 N 步 · 算子名）放在图片**左侧外侧**，垂直与图片顶边对齐，不遮挡内容。
  图片位置由 JS 按内容宽高比算好后居中（`positionCompareTags`）——
  `object-fit: contain` 会在格子里留白边，纯 CSS 只能贴格子、贴不到图。
- **点图放大**：预览区任意一张图点一下进全屏灯箱，先立刻显示手里的 420px 缩略图，
  同时按 1600 长边重算这一步并替换，标签上显示实际分辨率。
- **单图 / 对比可随时切换**：点任何图都先开单图，右上角「两张对比」切到并排
  （每张约 745×598，比主界面大得多），再点「只看当前」切回。
  看的是原图（第 0 步）时没有对比对象，按钮自动隐藏。
  窄屏（<1100px）自动改为上下叠放。点遮罩 / 点 × / Esc 退出。
- 算子行**固定高度 + 链内滚动**：空间不够时滚，绝不把行压扁——压扁会表现为
  「下一行的字压在上一行参数上」。

### 核验两个按钮

| 按钮 | 作用 | 写库 |
|---|---|---|
| 候选 1/2/3/4 | 直接跳到某一条已算好的候选；选中的那条描边加深，右上角小点标出闸门结论 | `edits.jsonl` 记一条 switch |
| 通过核验 | 标记该样本 `accepted=true`，左侧出现绿点 | `edits.jsonl` 记一条 accept |

候选按钮直接来自 `rounds`（查表 3 条 + AI 自拟 1 条，去重后最多 5 个），
**不重算、不调模型**，切一次约 200 ms（只重跑算子出预览）。
切到别的链会撤销该样本原有的「已通过核验」——核验针对的是具体某条链，不是这张图。

切到**闸门结论为拒绝**的候选时会弹一条警告，并把该样本标成「需复核」：
这条链能看、能改、也能导，但导出前必须有人知道它不是系统推荐的。切回通过/告警的链，
标记自动撤销——标记描述的是当前这条链，不是这张图的履历。

核验状态会进导出：

- **导出前先问**：这批有几张核验过，给你「只导已核验」和「全部导出」两个选择；
  一张都没核验时直接提示，只能全部导出。
- **文档里可见**：`流程配置.md` 头部写「样本数：4（其中 2 张已通过人工核验）」，
  末尾有「样本核验状态」表（样本 / 方案 / 核验 / 改过几处 / 得分）。
- **只导已核验时**：`debug_samples/` 和方案分组只算确认过的样本，
  `pipeline.json` 的 `covers` 按实际导出数重算，不会出现「写 6 张、包里 2 张」。
- 后端也拦了一道：没有核验样本时 `only_accepted=true` 返回 400，不会导出空包。

### 导出前会先报分组

点「导出流程配置」时，弹窗里先给一行结论：

> 本批会分成 **2** 组方案，1 组组内一致率低于 80%，需人工确认

要细节点「查看分组明细」，展开成表格（成像问题 / 处理链 / 样本数 / 一致性 / 结论）。

表格不折叠，直接摊开；超过 168px 在框内滚动（表头吸顶）。

这取代了原来左栏的「聚合成方案」按钮——那个按钮对导出结果没有影响（导出时反正要重算），
却会把结果缓存进批次：聚合之后又改了方案，再导出用的还是旧分组。
现在导出**每次都重算**，按钮去掉，信息挪到真正要决策的地方。

### 配置单里的方案分两类

- **分组方案**：诊断分组投票出的代表链，一批一份的主方案，带「组内一致率」。
- **样本专用**：分组覆盖不到的实际链——人工切过的、手改过的、AI 自主拼接的。
  这类链单独列一节，参数与节点清单同格式。

按「算子序列」而不是 `recipe_id` 归节：AI 拼出来的链 id 都叫 `ai_composed`，
算子顺序和参数各不相同，按 id 归成一节会把几条链写成一个参数表。
参数精修会给个别图微调参数，这类样本在逐张明细里标「参数微调」，方案里给的是组内多数那套。

另外两处「别让它静默」的处理：

- 某方案只有小图（< 0.2 MP）样本时，耗时表会标注 ms/百万像素 不可直接外推——
  192×192 上测出的 0.4 ms 折成 11 ms/MP，和 1280×960 上的 57 ms/MP 差一个量级。
- 导出链在整幅图上重算后若有样本判「拒绝」（多为全原生替换所致），
  配置单开头会点名列出，不再只藏在逐张明细里。

### 包的构成

默认只给人要看的三样：

```
流程配置.md        打开这个：节点顺序、参数、VM 模块、多分辨率耗时
compare/          原图|增强图并排，配完对照
debug_samples/    增强图本身，可直接导入 VM 试跑
```

JSON 是**默认不导出**的，导出弹窗里勾「同时导出机器可读配置」才会带上
`pipeline.json` / `manifest.json` / `edits.jsonl`。理由很直接：一份给流程搭建同事的包，
多三个他永远不会打开的文件，只会让"这堆东西怎么用"多一层解释成本。

切换勾选时会清掉上一版残留的 JSON，不会出现"这次没勾但包里还有"的情况。

### 怎么"给机器用"

勾了 JSON 之后，配套了一个小工具：

```bash
# 1) 把 pipeline.json 摊成核对表（CSV，带"配好了""实测耗时"两列留空给人填）
python scripts/use_export.py checklist data/exports/<批次ID>

# 2) 自检：按 stages 重跑一遍，和 debug_samples 里的图逐像素比
python scripts/use_export.py verify data/exports/<批次ID>

# 3) 跨实现核对：把 VM 跑出来的同名图放一个目录，和我们的产出比
python scripts/use_export.py verify data/exports/<批次ID> --vm-dir D:/vm_out
```

`verify` 输出每张图的均值差 / P99 / PSNR / 同像素占比，判读标准：

| 均值差 | 含义 |
|---|---|
| < 1 | 基本等价 |
| 1 – 4 | 实现差异（截断、取整、参数定义不同） |
| > 4 | 模块选错或参数没对上，回流程改 |

自检模式全部为 0，说明导出的图确实是按配置单跑出来的，配置单没跑偏。

### 全原生模式

导出弹窗里默认勾选「全部转成海康原生模块」，把海康没有原生模块的三个算子换成原生组合：

| 原算子 | 换成 | 差异 |
|---|---|---|
| `retinex` | `illum_norm` → `clahe(clip=1.5)` | 对数域多尺度 → 线性域背景校正 + 局部均衡，暗部提升弱一些 |
| `homomorphic` | `illum_norm` → `usm` | log 域同时压低频/提高频 → 拆成两步线性操作 |
| `bandpass` | `dog(k1=1, k2=3)` | 空域近似，选通频段不能对应原 low/high |

`illum_norm` 本身也归到原生（对应 VM 的「阴影校正」），但它做的是**相除**、VM 多为**相减**，
暗部放大程度不同，配完要比一次图。

替换是**近似不是等价**，所以配置单里会单列一张表说明每个替换的参数与差异，
`manifest.json` 的每条 item 也带 `native_swaps`。

底部是**候选编号按钮 1/2/3/4**：直接点某一条切过去，不重新生成。选中的那条描边加深，
数字右上角的小点标出闸门结论（绿可过 / 橙告警 / 红拒绝），悬停显示方案名、得分、算子序列。
要新候选得点「生成方案」。

两个按钮都做了防连点（请求未返回时按钮禁用），因为连点会读到上一次的状态。
后端此前有个 `UnboundLocalError`：候选耗尽时循环一次不执行，`nxt` 从未赋值，
直接 `if nxt:` 会抛 500 —— 表现就是「点两次就报 Failed to fetch」。现已在循环前显式 `nxt = None`。
主界面只留三块：诊断、算子链、预览。迭代记录 / 指标 / 伪影审计收进弹窗，
入口按钮上直接写结论（`迭代记录 4`、`指标 +0.252`、`伪影 通过`），不点开也能判断。

### 语义色

按工业场景的读法：**绿=可放行，橙=留意，红=不可用**。

| 语义 | 文字 | 底 / 边 |
|---|---|---|
| 通过 / 正向 | `#15803D` | `#ECFDF3` / `#A7F3D0` |
| 告警 / 中性 | `#B45309` | `#FFFBEB` / `#FDE68A` |
| 拒绝 / 负向 | `#B91C1C` | `#FEF2F2` / `#FECACA` |

颜色只承载判断，不用于装饰。三处例外是刻意留的中性：

- **平均亮度**不给红绿。调亮调暗都可能对，染成红的会误导"变暗=坏事"
- **迭代分数**统一中性色。一行里同时出现"绿色分数 + 红色拒绝"会让判断打架，
  颜色全部让给结论徽章
- **诊断标签**保持中性。成像问题本身不分好坏

即使某天打印成灰度，每个彩色元素旁边都带着文字（通过/告警/拒绝），不会失去信息。

### 算子链怎么改

- 每张卡片左侧挂该步输出的**缩略图** —— 一张烂图经过三步变清楚，中间态全可见
- 参数控件由 `SCHEMA` 自动生成，加新算子不用改前端
- 上移 / 下移 / 删除 / 加算子 / 改参数，改完即时重算预览
- 只有**人工改过**的步骤才标「已改」，链的来源写在标题上，不逐行重复

拖滑杆时**只重绘缩略图和右侧面板，不重绘链结构**——
否则 DOM 重建会让滑杆失焦，手感直接废掉。这条写在 `app.js` 顶部。

## 关键机制

### 三阶段，AI 只在最后一环动手

| 阶段 | 做什么 | 谁决定 | 谁执行 |
|---|---|---|---|
| 查表 | 从配方库按诊断优先级取 3 条 | 人写的映射表 | 固定执行 |
| **AI 自拟** | 现场拼一条新链，写出各算子参数 | **模型** | 模型 + 校验层 |
| 参数精修 | 对最优链和"分数更高但被拒"的链做一维参数扫描 | 搜索结果 | 代码 |

**AI 真的会改参数**：`compose.py` 要求模型直接给出 `{"op":"illum_norm","p":{"sigma":45}}`，
但出口有四道校验（`ops.normalize_stages`）：算子白名单、参数 schema、超界钳制、链首补 gray。
模型编的 `pseudo_hdr` 会被丢弃，`clip=99` 会被钳到 8.0，且这些处理都会显示在界面上。

**为什么不让模型直接调参**：它对 `clip=2.0` 和 `2.3` 没有区分能力。
所以"选哪个值"用测的（精修），"怎么组合"才用猜的（拼链）。

推荐时给「带告警」的方案扣 0.06 分——纯按分数选会推荐一条有伪影告警、
但只高 0.02 的链，工程上不划算。

精修的目标函数分两种方向：审计等级能改善时（reject→warn）允许分数掉 0.12，
只管把链救活；等级不变时只认实打实的提分。

### 耗时

单张 8–25 秒，波动主要来自模型思考长度（不是本地算子）。
`detail=low`、纯文本拼链已经把 token 压到很低，快不起来的是推理本身。
批量时可以在请求里传 `{"compose": false}`，只走查表 + 精修，约 2 秒/张。

### 伪影审计（闸门）

增强会把噪声和量化台阶一起放大。标注员可能把一团噪声标成缺陷，
这条**假标签**进训练集比漏标更毒。所以每条链先过闸：

| 判据 | 拒绝 | 告警 |
|---|---|---|
| 截断率 | > 10% | — |
| 噪声 | σ > 7.6/255 且放大 > 2.5× | σ > 5.1/255 且放大 > 2× |
| 台阶指数 | — | > 0.50 |

噪声必须「绝对 + 相对」双条件：只看比值会误杀 Retinex
（噪声底极低的图上 0.001 → 0.017，比值 8.7× 很吓人，但 σ 4/255 对标注无害）。

全部候选都被拒时**不会卡死流程**：给最不坏的一条并标 `需复核`。
预处理救不回来的图，本身就是结论——该改光源/曝光，而不是继续调算子。

### 批次聚合

30 张图各出一套参数等于没方案，标注员不会读 30 份说明。
按首选诊断分组 → 组内投票 → 出一组一条链。一致率低于 80% 的组标「需人工确认」。

### 改动回灌

每次人工修改都写进 `data/edits.jsonl`（add / remove / move / param / accept / reject）。
这是"AI 下次首推更准"唯一的语料来源，也是答辩时"闭环"两个字的实证。

## 已知限制

- **代理指标不是精度**。加权分只说明"信息量变多"，检出率必须在 VM 里跑真实样本才知道。
- **不生成 VM 工程文件**。VM 的流程文件是专有格式，导出的是一页配置单（节点/模块/参数），
  仍需人工在 VM 里搭，`use_export.py checklist` 只是把这件事变成逐行打钩。
- 本地规则诊断（`rules`）只判成像条件，判不了"缺陷是否可见"。要判那个得上视觉模型。
- 全原生替换是**近似**：`retinex` / `homomorphic` 换成背景校正组合后效果会弱一档
  （实测铜线样本 +0.707 → +0.603），配置前要比一次图。
- 批次聚合是投票制，不做分层抽样；样本极不均衡时组内一致率会失真。
- 单进程 JSON 存储，够单机演示，不适合多用户并发。
